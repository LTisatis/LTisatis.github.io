一、项目目标与交付方式

基于已选择的 Fuwari 卡片视觉型模板，搭建以中文文章和个人介绍为核心的静态博客，通过 GitHub Pages 发布到 https://<GitHub用户名>.github.io/。
第一版实现首页、文章详情、分页、标签与分类筛选、归档、搜索、关于页、RSS、深浅主题和 404 页面。暂不加入作品集、评论、登录、数据库、付费功能或网页写作后台。
采用“保留模板核心结构，优化配置、中文排版、移动端体验和发布流程”的方式实施。

二、模板、技术栈与改良原则

2.1 模板选择
使用 Fuwari 官方仓库作为代码基础，参考在线演示。
仓库：https://github.com/saicaca/fuwari
演示：https://fuwari.vercel.app/
Fuwari 已提供响应式布局、主题颜色、深浅模式、Pagefind 搜索、目录和 RSS，适合在现成功能上优化。模板采用 MIT 许可证，保留许可证和原有版权声明。
实施时记录导入的上游提交编号，建立独立项目历史；后续按需合并上游修复，不直接覆盖整个项目。

2.2 技术定位
Astro：路由、组件、内容渲染和静态页面生成。
TypeScript：配置、文章处理和组件逻辑的类型检查。
Markdown + YAML Frontmatter：保存文章正文和元信息。
Astro Content Collections：读取文章并校验字段。
Tailwind CSS + Typography：页面布局和正文排版。
Svelte：保留模板已有的交互组件。
Expressive Code：沿用模板代码展示与复制功能。
Pagefind：构建静态全文搜索索引。
Astro RSS、Sitemap 集成：订阅源与站点地图。
Node.js + pnpm：开发运行环境和依赖管理。
Git + GitHub：版本历史和远程源码仓库。
GitHub Actions + Pages：自动检查、构建、发布。

模板在规划时声明使用 Astro 5、Tailwind CSS 3 和 pnpm 9.14.4，因此本项目沿用其依赖体系及锁文件，不混用前面示例中的 npm 工作流，不在首次搭建时顺带升级框架大版本。
依赖参考：https://github.com/saicaca/fuwari/blob/main/package.json
本地与 CI 使用 Node.js 24 系列，并固定一致的补丁版本。已检测到本机安装了 Node.js 24.16.0 和 Git；pnpm 在实施时验证可用性并匹配模板要求。

2.3 默认视觉方案
（1）保留横幅、个人信息侧栏和文章卡片布局。
（2）采用模板蓝紫色方向，固定品牌主色，隐藏访客调色功能。
（3）保留浅色、深色和跟随系统三种主题方式。
（4）桌面正文约 18px，手机正文约 17px，行高约 1.8。
（5）正文阅读宽度控制在约 720～800px。
（6）手机端将侧栏折叠为紧凑信息区，优先展示文章内容。
（7）缩短首页横幅高度，保证常见手机首屏能够看到文章入口。
（8）无个人图片时，使用原创 CSS 渐变横幅和文字头像；不将模板演示图片当作个人素材。
（9）保留轻量过渡效果，同时尊重系统减少动画设置。
（10）中文字体优先使用系统字体，避免依赖大型远程字体。

三、实施步骤与产出

3.1 阶段 1：环境、模板与基础工程
1. 导入 Fuwari 源码，记录上游提交，保留许可证。
2. 使用 pnpm 锁定依赖安装。
3. 运行模板检查和完整构建，确认基础版本可用。
4. 建立 Git 忽略规则，排除依赖、构建产物和本地私密文件。
5. 将模板原始状态与个人改动分成独立提交，方便比较和回退。
6. 保留模板目录、配置方式和现有 URL 工具，避免重建一套平行架构。
产出：可启动、可检查、可构建的本地博客基础。

3.2 阶段 2：站点信息与中文化
统一配置博客名称、副标题、个人昵称、简介、导航和公开链接。
模板语言使用其支持的 zh_CN 配置，HTML 输出语言规范为 zh-CN。
日期展示统一采用中文格式和 Asia/Shanghai 时区。
导航固定为首页、归档、关于，并提供搜索与 RSS 入口。
标签和分类通过模板侧栏及归档筛选访问。
未提供的社交链接隐藏，不保留原作者或演示链接。
模板代码许可证与个人文章授权分开处理；关闭默认套用在个人文章上的 CC 授权，使用“版权所有”说明。
开发时可用“个人博客”“记录学习与生活”等占位文字；正式发布前替换站点名称、署名与个人介绍。
产出：完成中文化、具有统一个人信息的站点框架。

3.3 阶段 3：文章数据与发布规则
沿用 Fuwari 的实际字段名称，避免使用此前概念示例中的另一套命名。
字段参考：https://github.com/saicaca/fuwari/blob/main/src/content/config.ts
title：必填，文章标题。
published：必填，发布日期。
updated：可选，更新日期。
description：本项目要求填写，用于摘要和页面描述。
image：可选，文章封面。
tags：标签数组，默认空。
category：可选，单个分类。
draft：是否草稿，默认 false。
lang：可选，单篇语言覆盖。

文章示例：
---
title: 我的第一篇博客
published: 2026-09-09
description: 记录搭建个人博客的过程。
tags: [博客, 随笔]
category: 生活记录
draft: false
---

## 开始记录

这里填写正文。

内容处理约定：
（1）每篇文章使用稳定的英文或拼音文件标识；改标题不改网址。
（2）保留模板 /posts/<文章标识>/ 路由。
（3）正式文章按发布日期降序排列，同日按标识稳定排序。
（4）统一公开文章查询：排除草稿和未来日期文章。
（5）首页、归档、标签统计、上一篇下一篇、详情路由、RSS 和搜索均遵循同一发布规则。
（6）本地开发允许预览草稿；正式构建不生成其页面。
（7）日期按日发布，未来日期不会自动触发上线；需推送或手动运行工作流重新构建。
（8）私人草稿保存在公开仓库之外，不能依赖 draft 字段隐藏源码。
现有模板主要依据草稿字段过滤，因此未来日期过滤和各入口一致性属于本项目需要补充验证的改良项。
查询参考：https://github.com/saicaca/fuwari/blob/main/src/utils/content-utils.ts
产出：文章模板、统一发布规则和一篇完整示例文章。

3.4 阶段 4：页面与阅读体验改良
首页：横幅、紧凑个人介绍、文章卡片；每页 8 篇。
分页：沿用模板现有分页路由。
文章详情：标题、摘要、日期、正文、目录、标签、前后文章。
归档：沿用 /archive/，按年份整理并支持标签与分类筛选。
关于：沿用 /about/，以 Markdown 维护个人介绍。
搜索：保留模板搜索入口与结果交互，不另外增加重复搜索系统。
404：生成静态 404 页面，提供首页和归档入口。

阅读体验重点：
（1）修正中文长标题、无封面卡片和摘要长度不一致的布局。
（2）正文支持列表、引用、表格、图片、代码及模板已有数学公式。
（3）宽表格与长代码在自身区域内滚动，避免撑宽页面。
（4）保留图片查看、代码复制和目录定位功能。
（5）手机端目录提供可折叠入口。
（6）主题切换后保留用户选择，页面跳转不丢失交互。
（7）图片提供尺寸与替代文字；横幅与封面使用压缩后的本地资源。
产出：使用真实中文长文也能正常阅读的桌面与手机界面。

3.5 阶段 5：搜索、SEO 与订阅
沿用完整构建命令：先构建 Astro，再运行 Pagefind。
搜索主要索引文章正文与标题，排除导航、侧栏等重复内容。
在正式构建预览中验证中文关键词搜索。
为页面设置独立标题、描述和规范链接。
配置 RSS、站点地图、robots.txt，并使用同一正式站点地址。
分享图片使用文章已有封面；没有封面时不引用模板演示图。
检查 RSS 和站点地图不包含草稿、未来文章或测试内容。
产出：可用的中文搜索、订阅源和一致的公开页面元信息。

3.6 阶段 6：GitHub Pages 自动发布
创建或使用用户的公开仓库：<GitHub用户名>.github.io。
正式地址：https://<GitHub用户名>.github.io/。
Astro 配置使用静态输出、根路径 / 和统一尾斜杠。个人主页仓库不添加仓库名路径，不创建独立域名的 CNAME 配置。

GitHub Actions 工作流：
1. 在拉取请求中执行检查与构建，不发布。
2. 在 main 分支推送或手动触发时执行发布。
3. 安装固定 Node.js、pnpm 和锁文件依赖。
4. 执行 Astro 检查及不自动改写文件的静态检查。
5. 执行模板完整构建，确保包含 Pagefind 索引。
6. 检查公开产物后上传 dist。
7. 使用 GitHub 官方 Pages 部署机制发布。
8. 配置必要权限：读取仓库、写入 Pages、OIDC 身份令牌。
9. 检查失败则终止发布，保留此前成功站点。
仓库 Pages 发布来源设为 GitHub Actions。采用工作流内置身份，不在源码中存放个人访问令牌。
部署指南：https://docs.astro.build/en/guides/deploy/github/
产出：可通过 github.io 访问，并能随提交自动更新的博客。

四、测试、验收与维护

4.1 上线前验收
（1）类型检查、静态检查及正式构建全部通过。
（2）首页、文章、分页、归档、关于和不存在页面的行为正确。
（3）文章深层链接可直接打开和刷新。
（4）中文标题、中文标签、无封面文章和空搜索结果显示正常。
（5）搜索能找到新增文章，排除草稿与未发布文章。
（6）用一篇含特殊标记的草稿检查生成页面、搜索索引、RSS 和站点地图，确认没有泄露。
（7）360px、768px、1440px 三种宽度下无意外横向滚动。
（8）键盘可操作菜单、搜索、目录与主题切换。
（9）页面跳转后搜索、复制代码、目录和图片交互仍然有效。
（10）图片没有失效，正式链接没有残留演示域名。
（11）发布成功后检查 HTTPS、RSS、搜索索引文件和 404 响应。
对公开文章过滤和日期排序加入小规模自动化测试；页面体验通过构建预览和浏览器验收确认。

4.2 日常写作
创建文章 → 填写元信息和正文 → 添加配图 → 本地预览 → 检查与构建 → 提交并推送 → 查看 Actions 结果 → 确认线上文章。
搜索依赖构建生成的索引，因此最终检查使用 pnpm build 后的 pnpm preview。

4.3 更新与恢复
保留依赖锁文件，升级在独立分支进行。
上游模板改动按需合并，不自动整体替换。
CI 报错时先修复，避免绕过检查发布。
线上回退通过撤销问题提交并重新部署完成。
GitHub 仓库之外保留文章和原始图片备份。
项目说明记录模板来源、启动命令、写作格式、部署方式与回退步骤。
