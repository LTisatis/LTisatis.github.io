# 评估与维护

仅在评估、修改或发布本 skill 时读取。普通科研目录整理无需加载本目录，也不自行修改技能规则。

## 当前证据与边界

初版在隔离项目上进行过一次真实整理：14 个原有文件均有去向；11 个文件内容不变；修改的配置路径和 29 个本地文档链接检查通过。该案例只说明一个模拟任务可执行，不证明真实项目普遍受益。

1.1.0 随包提供离线脚本回归测试及 `cases.json` 行为案例。脚本测试验证盘点工具，不验证模型是否正确触发或执行 skill。未开展有/无 skill 的同条件对照、路由实测、跨模型迁移或成本收益评估；这些项目不得写成“已通过”。行为案例中的期望是验收标准，不是执行结果。

2026-10-15，Windows / Python 3.12 下实测：7 项盘点回归中 6 项通过、1 项因缺少符号链接创建权限跳过；真实 Windows junction 与隐藏属性检查通过。8 份行为任务与隔离输入已成功生成，生成器的拒绝覆盖及输入基线检查通过；尚未把这 8 个任务交给模型执行。格式、包内相对链接及 JSON 校验通过。这些结论只适用于实际检查的版本和环境。

按“正文 + 项目记录模板”估算一次项目记录任务的加载文本，从初版 6,495 字符降为本版 5,512 字符。该计数不包含会话、工具文档和模型推理，不能换算为实际耗时、token 节约或质量收益。

## 行为、路由与成本评估

用 `prepare_cases.py` 在一个尚不存在的临时目标下生成 `cases.json` 中的材料和任务提示：

```text
python "<skill目录>/evals/prepare_cases.py" "<新的隔离测试目录>"
```

每个案例使用独立项目副本。路由评估只提供案例提示和材料，不点名此 skill，观察选中、漏选和误选；执行评估可以明确要求使用此 skill。分开记录“未选中”“已加载但执行错误”“指令缺陷”“工具失败”。检查实际文件和操作记录，不只看最终答复。

对照评估使用同一模型、工具、权限、任务预算和等价的新会话。有 skill 和无 skill 各跑一份独立副本；避免前一次输出泄露到后一次。记录数据损坏/越界/无授权写入、路径有效性、事实编造、未处理项、人工返工，并记录耗时、工具调用数、加载字符数或 token 数（不可得时注明）。工具和文档更多并不自动代表更好。

`cases.json` 中 `holdout: true` 的案例用于后续迁移检验；不得声称当前已跑过。未来若用这些案例调整了技能，另留新案例作留出测试。只要发生数据覆盖、范围外改动或只读任务写入，就先修复再入库；成本是否值得增加，结合真实任务和用户反馈判断，不设无依据的统一速度门槛。
