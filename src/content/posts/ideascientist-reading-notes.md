AI 能写出一份像论文的研究计划，已经不难。更难的问题是：它提出的想法有没有文献依据？是不是把已有方法换了个名字？看起来可行的方案，究竟要怎样验证？

*IdeaScientist: Orchestrating Agents for Grounded Scientific Ideation* 研究的正是这个环节：<strong>给定一个研究问题和现有方法尚未解决的挑战，生成有依据、可检验的研究方案。</strong>论文的 arXiv v1 发布于 2026 年 10 月 2 日。本文依据这一版本及作者提供的论文源码阅读，重点讨论方法、实验是否严谨，以及对我们使用 Codex 的启发。

> <strong>先看重点</strong>
>
> - <strong>最值得借鉴的流程：</strong>从相近工作找缺口，围绕共同的问题结构去其他领域找机制，再写成可以被实验推翻的方案。
> - <strong>最值得注意的结果：</strong>在 Qwen 骨干的比较中，未训练框架已领先最强同骨干基线 12.9 个百分点；强化学习再提高 1.1 点。
> - <strong>最需要谨慎的解读：</strong>训练版的 14.0 点综合分优势中，约 9.3 点来自“跨场景机制迁移”这一指标。人工评审没有显示它显著胜过 DeepScientist。
> - <strong>对我们的直接启发：</strong>先把证据、缺口、候选机制和验证计划分别留下，再让 Codex 成稿。方案写得完整，不代表方案已经成立。

## 1. 论文到底在解决什么问题？

很多“自动科研”系统会连续完成提出想法、写代码、做实验和写论文。这样做很有吸引力，却不容易定位成功来自哪里：是想法好，还是代码实现可靠，或者系统试了很多次，终于找到一个有利结果？

IdeaScientist 把<strong>科研构想生成</strong>单独拿出来评估。它的输入由两部分组成：

- <strong>问题定义：</strong>任务接收什么输入，需要产生什么输出。
- <strong>挑战：</strong>现有方法在哪个方面不能满足需求，例如质量、延迟、隐私或适用条件。

它的输出是一份研究方案，包括方法、相关工作、评价计划、预测和局限。论文没有系统执行这些方案，因此评价对象主要是<strong>方案文本及其论证</strong>。

这里有一个容易忽略的前提：系统并不是从完全开放的世界中自行发现值得研究的问题。测试中的问题和挑战，由已经写成的论文重构而来。这使任务更清楚，也意味着结果不能直接代表现实科研中“从模糊现象找到问题”的能力。

## 2. 核心方法：找缺口、找机制、写方案

先把几个词翻译成人话。

<strong>研究缺口</strong>是现有方法还不能解决的具体困难。例如，“某类方法在长输入下需要重复进行昂贵计算，导致延迟上升”。只说“效率还有提升空间”，还不足以指导研究。

<strong>机制</strong>是一个方法为什么起作用的因果或设计逻辑。例如，先用便宜步骤筛选，再把昂贵计算集中到少量候选上。机制可以跨领域使用，但输入条件、误差代价和适配方式必须重新检查。

<strong>可证伪预测</strong>是提前说明什么观察会支持方案、什么观察会推翻方案。它让研究计划从“应该会有效”变成“可以据此决定是否保留”。

### 三个主要角色各做什么？

| 阶段 | 主要问题 | 必须留下的产物 |
|---|---|---|
| Gap Finder：找缺口 | 最相近的已有方法为什么还没解决挑战？ | 带文献出处的方法缺口 |
| Innovator：找机制 | 其他问题场景有没有解决类似困难的机制？ | 候选机制、共同结构、适配条件 |
| Report Writer：写方案 | 怎样把候选机制变成可执行的研究计划？ | 方法细节、对照实验、预测和失败边界 |

另外，<strong>调度者</strong>负责安排步骤和决定是否回到前一阶段；<strong>论文阅读者</strong>在独立上下文中阅读全文，返回针对问题的摘要；<strong>评审者</strong>检查证据和新颖性，要求保留、修改或放弃候选方案。

这套流程的价值，在于让不同阶段的错误有地方可以追查：缺口引用错了，就回去读论文；迁移条件不成立，就修改机制；评估计划无法区分方案与基线，就重写实验。最终文本之前有一串可以检查的中间产物。

### 一个帮助理解的例子

下面是<strong>解释流程的假设示例，不能当作论文已经验证的结果</strong>。

假设我们想降低文献检索工具的响应延迟，同时尽量不损失相关文献的召回率。

第一步，找缺口：检查相近系统，确认延迟究竟来自大范围检索、全文读取，还是昂贵的重排序。假如主要瓶颈是对所有候选都使用昂贵模型，那么缺口就具体了：当前流程没有区分“需要精细判断”和“明显不相关”的候选。

第二步，找机制：推荐系统中常见的两阶段处理，可以提供一个候选思路——先以较低成本召回候选，再对少量候选精排。这里的共同结构是：<strong>候选很多，精细判断昂贵，而最终需要的结果较少。</strong>

第三步，检查适配：文献检索可能更怕漏掉罕见但关键的论文。第一阶段如果过早删除候选，第二阶段就无法补救。因此需要考虑召回保护、候选数量和不确定性，而不能只把推荐系统的名字搬过来。

第四步，写可检验方案：在同一查询集合上，与现有流程比较延迟、召回率和遗漏的关键文献。若加速来自大量漏检，或者便宜筛选本身已经很慢，这个方案就需要修改或放弃。

这个例子也说明：<strong>跨领域迁移本身不能保证创新。</strong>如果目标领域早已有类似做法，重新发现它只能算有依据的借鉴。创新还要与最接近的本领域工作比较。

### 论文如何约束“听起来很新”的想法？

创新者不能只写一句“借鉴某领域的方法”。它需要交代来源问题、借用机制、两边共享的结构、目标场景的适配、成立假设，以及与本领域近邻工作的差别。方案撰写者再把这些内容落实成模型或方法细节和评估计划。

两个角色都使用文献检索工具。区别主要来自检索问题和任务要求：找缺口偏向本领域相近工作，找机制偏向不同问题场景。读者不应把它理解为某个神奇的跨领域搜索引擎。

## 3. 数据和训练：系统从哪里获得依据？

### 文献库与训练样本是两件事

论文构建了 Svalbard Idea Vault 离线文献库，报告约有 <strong>470 万篇文献、280 万篇全文</strong>，并从文献中重构约 <strong>277 万条研究构想记录</strong>。每条记录包含问题、挑战、缺口、直觉和方案等内容。

这里的“人类参考”来自人类撰写的论文，但结构化记录主要由模型提取。它并不是数百万份研究者亲自标注的构思过程，也不记录作者真正如何一步步想到方法。

用于训练与评估的机器学习方法论文，共筛选出 <strong>14,977 篇</strong>：14,500 篇训练、200 篇验证、277 篇测试。作者过滤了综述、数据集、基准和一些非方法型工作，并对引用全文可用性提出要求。

在重构参考方案时，作者移除已测得的实验结果，保留方法设计和相关内容。这样可以减少“把结果直接告诉系统”的问题，但参考方案仍然来自事后完成的论文。作者抽查 50 个问题输入，没有发现目标方法泄露；<strong>0/50 的抽查结果有参考价值，不能证明全量数据完全没有泄漏。</strong>

### 为什么不只给最终方案打分？

长流程最终得分低，可能是缺口找错、机制适配失败，也可能只是报告遗漏了评估计划。如果只给最后一步奖励，很难告诉前面的角色该改哪里。

论文因此分别训练三个专业角色，使用 LoRA 和异步 GRPO。可以粗略理解为：LoRA 让模型通过较小的附加参数学习角色任务；GRPO 让同一任务的多个候选输出相互比较，再据此更新模型。调度者没有随这三个角色一起训练。

训练奖励结合了几种信号：

- <strong>独立质量：</strong>产物是否具体、合理、有证据。
- <strong>参考相符程度：</strong>是否抓住参考研究中的实质内容，同时允许有效的替代思路。
- <strong>引用重合：</strong>引用集合与参考集合的 F1，也就是精确率和召回率的综合。
- <strong>流程合规：</strong>工具调用、格式和必需字段等是否满足要求。

论文将前三项平均后通过有效性门控，再与流程奖励组合。<strong>引用重合不等于引用真的支持论断；阶段奖励提高，也不等于真实科研成功率提高。</strong>理解这个区别，才能正确看待训练曲线。

## 4. 主要结果：提高了多少，具体提高了什么？

### 先读懂评分表

主评审模型是 Qwen3.6-27B，另外四个模型用于交叉核验。方案质量由相关性、清晰度、具体性、可执行性、技术合理性和潜在影响六项构成。

新颖性由三项组成：

| 指标 | 实际含义 | 阅读时注意什么 |
|---|---|---|
| All | 相对于提供给评审的、不限时间的相近文献，方案有多少新增内容 | 并非穷尽全世界论文后的查新结论 |
| Cutoff | 相对于时间截断前的相近文献，方案有多少新增内容 | 不控制基础模型参数中的所有知识 |
| In-domain | 是否有明确的跨问题场景机制迁移，并解释共同结构与适配 | 这是二元判断的比例，名称容易让人误解 |

All 和 Cutoff 是评分后换算到百分制的数值，In-domain 则是满足条件的方案占比。三个分项被等权平均为“平均新颖性”，再与“平均方案质量”等权平均得到综合分。

因此，综合分既包含质量与新增内容的判断，也包含<strong>某种特定研究行为是否出现</strong>。它不能直接读成“研究成功的概率”。

### 277 个测试任务上的主要比较

| 系统与骨干模型 | 平均新颖性 | 平均方案质量 | 综合分 |
|---|---:|---:|---:|
| DeepScientist · Qwen3.6-27B | 43.8 | 77.5 | 60.6 |
| IdeaScientist-Base · Qwen3.6-27B | 66.9 | 80.0 | 73.5 |
| IdeaScientist-Trained · Qwen3.6-27B | 68.8 | 80.4 | 74.6 |
| Claude Code · Claude-4.8-Opus | 51.9 | 85.5 | 68.7 |
| Codex · GPT-5.4 | 54.7 | 84.4 | 69.5 |
| IdeaScientist-Base · GPT-5.4 | 61.0 | 82.8 | 71.9 |
| IdeaScientist-Base · Claude-4.8-Opus | 69.8 | 85.7 | 77.7 |

这里摘录了与讨论最相关的系统；完整分项及其他骨干模型的比较见论文 Table 1。

<strong>同骨干比较最有解释力：</strong>训练版比 DeepScientist 高 14.0 个百分点，其中未训练框架已经贡献 12.9 点，训练再增加 1.1 点。训练版相对 Base 的平均新颖性增加 1.9 点，方案质量增加 0.4 点。

这说明，在这套任务和评价下，流程组织带来的变化比后续训练的增量更大。但流程同时改变了分工、提示、检索和修订，不能仅凭这张表认定某一个因素造成了全部提升。

不同骨干的表格也不能用来概括“27B 模型全面胜过更强的模型”。Claude 骨干的 IdeaScientist-Base 综合分达到 77.7；Claude Code 与 Codex 在方案质量项上的分数，也高于训练版 Qwen 系统。<strong>对用户而言，更相关的问题是流程能否改善自己的任务结果。</strong>

### 拆开看那 14.0 点优势

根据论文的评分权重，综合分可以写成：

$$
\mathrm{Overall}=\frac{\mathrm{All}+\mathrm{Cutoff}+\mathrm{Transfer}}{6}+\frac{\mathrm{Quality}}{2}
$$

这里用 Transfer 表示论文名为 In-domain 的迁移比例，方便理解。用表中的分项计算训练版相对 DeepScientist 的差距：

| 分项 | 原始分数差 | 对综合分差距的贡献 |
|---|---:|---:|
| All | 67.3 − 57.6 = 9.7 | 约 1.62 点 |
| Cutoff | 68.3 − 58.5 = 9.8 | 约 1.63 点 |
| 跨场景迁移比例 | 70.9 − 15.2 = 55.7 | 约 9.28 点 |
| 平均方案质量 | 80.4 − 77.5 = 2.9 | 约 1.45 点 |

合计约 14.0 点，其中约三分之二来自迁移指标。

> <strong>这是我们根据论文数据做的算术分解，不是作者另做的一组实验，也不是因果分析。</strong>它说明总分对权重与指标定义敏感。如果去掉迁移项，让剩余两项新颖性的平均值与方案质量重新等权，训练版仍领先约 6.3 点。不过这已经是另一个评价口径，不能用它替换论文报告的结果。

## 5. 实验是否严谨？分开看证据强度

我的判断是：<strong>这篇论文对流程在其基准上的价值提供了较丰富的证据，但对真正的科研原创性与实验成功率，证据仍有限。</strong>下面说明依据。

### 扎实的部分：没有只依赖一张主结果表

作者报告了数据划分、角色训练与工具设置，比较多个系统，并检查角色消融、检索范围、推理预算、多模型评审和人工盲评。这些实验让读者能够区分流程、训练与评价的一部分影响。

所谓<strong>消融实验</strong>，就是去掉或替换系统的一部分，观察表现是否改变。加入缺口发现者和创新者后，新颖性提高，支持这些步骤在当前设置下有用。不过新增步骤也引入更多计算，仍不能完全隔离“专业分工”与“花了更多资源”的贡献。

### 跨领域检索增加了迁移，原创性的提升较小

将创新者从同领域检索改为跨领域检索后，迁移比例从 <strong>36.3% 提高到 67.0%</strong>。All 和 Cutoff 的提升分别约为 5.3 和 3.7 个百分点。

作者还做了更严格的“机制非显然性”检查：让评审根据最接近的已有工作提出可能的机制，再比较生成方案是否超出这些容易想到的候选。这项指标只从 <strong>33.5% 提高到 35.7%</strong>。

两类结果应一起看：系统明显更经常进行跨场景迁移，但对“提出不容易从近邻工作想到的机制”，观察到的提升小得多。小幅提升不能证明机制没有价值，却提醒我们别把“跨领域”自动等同于“原创”。

### 人工评审没有完全支持自动排名

两名标注者对 50 个任务的方案做匿名成对比较。训练版对多数基线的胜率为 75% 至 92%；对 Base 为 <strong>57%</strong>，对 DeepScientist 为 <strong>43%</strong>，后两项差异都没有达到统计显著。

怎样理解“没有显著差异”？样本中的偏好不足以清楚排除随机波动。<strong>它不证明两个系统完全一样，也不能因为 43% 低于 50% 就宣布 DeepScientist 显著更好。</strong>尤其在只有 50 个任务时，细小差距需要更充分的评价。

另外，两位专家的方案质量评分相关系数为 0.56；表现较好的三个模型评审与专家平均分的相关系数约为 0.51 至 0.59。它们有一定一致性，但距离可以互换还有明显差距。

这也解释了为什么自动评审很适合快速筛选，却不足以单独裁定研究价值。论文的数据重构、部分生成与奖励、主评审涉及相同模型家族，多评审能缓解单一偏好，却不能完全排除共同的表达风格偏好。

### 时间截断减轻泄漏，但不是严格预测未来

生成时，检索限制在 <strong>2026 年 1 月 1 日以前</strong>的文献；训练、验证和测试的目标论文都来自该日之后，并在这些目标论文中划分留出集。

这个设计控制了检索工具能读到什么，但有两点边界：一是基础模型参数中的知识难以完全控制；二是训练目标本身也来自截断后的论文，因此不能说整个系统只用截断日前的知识学习。

作者做了标题记忆探测，每个模型抽查 10 篇目标论文，没有发现明显标题记忆。这是有用的排查，但模型记不住标题，仍可能熟悉相近的方法或改写后的内容。

更稳妥的表述是：<strong>系统在受限文献检索条件下，对留出的论文问题进行构想生成。</strong>将它称为“预测未来研究”，需要更严格的训练时间控制、前瞻收集任务和结果验证。

### 训练有收益，但最终方案的增量有限

三个角色的验证奖励都提高约 10 个百分点，说明训练成功优化了阶段目标。端到端综合分则只提高 1.1 点，人工比较也没有显示训练版显著优于 Base。

这不是训练无效的证据。它更像一个提醒：<strong>优化中间步骤，未必能等比例改善最终结果。</strong>在我们的任务里，不能仅凭 Codex 的回答更完整、更符合模板，就认为科研判断变好了。

### 资源与真实执行仍是重要缺口

外部系统保留原有智能体循环，所有系统没有统一严格的总调用量和计算预算。结果可能同时反映检索策略、流程组织、迭代次数和资源投入。补充预算实验也显示，增加推理轮数能够提高完成率及报告阶段奖励。

论文的训练设置规模不小：每个角色使用 40 个节点、每节点 8 张 H100。这个配置不能直接换算为总费用，论文缺少完整的 GPU 小时与运行时间信息。训练版每个方案的生成 token 总量比 Base 约少 11.1%，也不等于总成本或延迟减少同样比例。

最关键的缺口仍是：<strong>方案没有经过系统性的实际实验验证。</strong>技术上听起来合理，可能在代码实现、数据、收敛、测量或预算阶段失败。论文能支撑哪些结论，可以按下面的层次理解：

| 结论 | 目前证据能支持到哪里 |
|---|---|
| 这套流程改善其基准上的方案指标 | 支持较充分，有主结果与多项补充检查 |
| 跨领域检索增加结构化迁移行为 | 有直接证据 |
| 系统全面提升科研原创性 | 支持有限，依赖指标，严格检查的提升较小 |
| 强化学习显著改善最终方案 | 自动评分有小幅增量，人工证据不充分 |
| 系统提高真实科研成功率 | 没有直接验证 |

## 6. 论文中的案例，应该怎样读？

附录有一个关于推理训练采样的案例：训练时，一个问题可以让模型生成多次回答，再使用这些回答更新模型。如何把有限的采样预算分配给不同问题，就是研究挑战。

训练版提出，先查看部分推理过程，再继续采样，尝试区分两类困难题：一种题模型有机会学会，只是当前不稳定；另一种题暂时超出能力范围，多采样也不容易获得有用信号。方案希望把资源更多留给前者。

这个思路容易理解：<strong>“很难”不总意味着“值得无限追加计算”。</strong>但关键假设也很明显：部分推理能否可靠判断题目属于哪一类？额外诊断的开销是否超过节省的采样？判断噪声会不会让真正有价值的困难题被放弃？

案例的意义在于展示系统能形成机制、假设和评估方向。它没有展示该生成方法已经跑出更好的训练结果。读附录时，也应保留这种区分。

## 7. 对我们使用 Codex 的具体启发

我们此前在[《AI 时代的科研工作流总结》](/posts/ai-research-workflow/)中讨论过资料组织、研究过程记录，以及回答过度展开和术语太多的问题。IdeaScientist 给出的启发，可以落到这些真实瓶颈上。

### 精读论文时，增加一张“机制卡”

只记录问题、方法名和主要分数，过一段时间很难重新使用。建议每篇论文另留一段简短记录：

| 字段 | 要回答的问题 |
|---|---|
| 问题与挑战 | 作者究竟要解决什么具体困难？ |
| 最近工作 | 最相近的方法是什么，它为什么不够？ |
| 核心机制 | 新方法通过什么步骤解决困难？ |
| 成立条件 | 依赖什么数据、假设或计算条件？ |
| 证据与边界 | 哪项实验支持哪条主张，哪些情况没有验证？ |
| 可迁移线索 | 我们的问题是否也具有同样结构？ |

每条关键判断都留下论文位置。不要让 Codex 把“作者的主张”“实验观察”和“我们的推测”揉成同一句确定结论。

### 构思时，分阶段保存，而不是一直扩写最终报告

可以在现有研究文件夹中固定保存六类产物：<strong>问题定义、文献证据、方法缺口、候选机制、质疑记录、验证计划</strong>。文件名与目录可以按项目习惯设置，不必为了形式增加一套复杂系统。

每一步给 Codex 一个明确的停止条件。例如，找缺口阶段先交付两三个带出处的具体缺口，证据不足就标记待查；不要为了填满格式直接推断。候选机制阶段再检查本领域是否已有类似工作。只有证据与机制可以对上，才继续写完整方案。

这样也能改善可读性：我们先看决定方案是否成立的几条信息，再决定是否需要长报告。篇幅服务于判断，而非每一步都扩写成论文。

### 把跨领域灵感写成可以检查的迁移依据

要求 Codex 对每个机制回答五件事：来源是什么、两边哪里相同、目标场景怎样修改、成立条件是什么、最容易在哪种情况下失败。

同时保留一个本领域强基线和一个简单方案。复杂方案如果只比一个弱对照好，就很难说明跨领域机制提供了什么。若简单方案已经解决问题，也没有必要追求更复杂的角色流程。

### 给评审者明确的反方任务

“请评价这个方案”容易得到一段鼓励性的意见。更有用的要求是：找出最接近的已有工作，检查引用是否支持主张，指出最脆弱的假设，并设计一个尽快发现失败的实验。

另一个角色或新的对话可以提供复查视角，但<strong>同一模型多次赞同，不构成独立验证</strong>。关键数字要回到原表，重要引用要读原文，方法主张最终要用数据和实验判断。

### 用最小验证来决定是否继续

在一个机制上花很多时间之前，先找出最容易导致失败、又可以低成本检查的假设。例如，迁移方案依赖某种信号区分两类样本，就先测这个信号是否具有区分度，而不是立即搭建整套训练系统。

最小验证至少应写清：对照是什么、观察什么、怎样算值得继续、怎样算应当放弃。允许失败成为一个有效结果，能够减少“已经写了很多，所以一定要继续”的惯性。

> <strong>我们应先迁移可检查的研究习惯。</strong>提示、角色分工、项目说明或 skill 可以复用流程，但它们不等于论文中的 LoRA 参数更新与 GRPO 训练。也没有证据表明日常 Codex 使用需要复刻论文的文献库和算力规模。

## 8. 一份可以直接复用的任务要求

下面这段适合放在下一次精读或构思任务开头。它并不能保证产生好方案，但能让中间过程更容易检查。

> 请围绕我给定的问题与挑战，按以下顺序工作：
>
> 1. 先确认任务输入、输出和成功标准；不明确的地方单独列出。
> 2. 阅读最接近的已有工作，提出至多三个具体方法缺口，每个缺口附出处和证据。
> 3. 针对有证据的缺口，给出候选机制。涉及跨领域借鉴时，说明共同结构、适配、假设和失败边界。
> 4. 检查本领域是否已有类似方法，并保留简单方案与强基线。
> 5. 先写最容易推翻候选方案的检验，再给出最小验证计划。
> 6. 最后整合成研究方案。区分作者主张、观察结果和我们的假设，不虚构实验结果。
>
> 每个阶段先给简短结论与关键证据，必要时再展开术语和细节。证据不足就标记待查。

## 9. 读完后，最该记住什么？

IdeaScientist 把构想生成整理成了一条值得借鉴的路径：<strong>找准现有方法的不足，寻找有适配依据的机制，主动质疑，再用实验决定是否保留。</strong>

它的实验支持这套流程提高了当前基准上的方案指标，也清楚展示了跨场景迁移行为的增加。但综合分依赖评价定义，人工评价与自动排名有差异，真实执行仍未验证。

对我们而言，实践的起点可以很小：下一篇论文多留一张机制卡，下一个研究想法先写反证条件，下一份 Codex 报告明确证据和假设。等这些做法实际减少了遗漏和返工，再决定是否需要更多自动化。
