# 友链与评论维护说明

## 当前状态（2026-09-28）

博客已接入友链页面和 Waline 客户端，Vercel 与 Neon 免费服务已开通，首个管理员已注册。免登录提交、持久保存、邮箱隐藏与限流已通过接口验证。正式发布通过 GitHub Actions 完成。

## 友链维护

编辑 `src/data/friends.ts` 的 `friends` 数组；按数组顺序显示。

```ts
{
  name: "朋友的网站",
  url: "https://example.com/",
  description: "对方网站的一句话介绍",
  avatar: "https://example.com/avatar.png", // 可省略，也可填写本站 /media/ 下的图片
}
```

网站地址必须是 http/https 完整地址，不允许包含用户名或密码。头像失败显示文字头像。
申请留言不自动进入列表，确认后手动添加。友链页为 `/friends/`，导航与手机菜单共用配置。

## 开通云端评论

1. 登录 Vercel，选择免费 Hobby；连接 Neon 免费方案。不要启用付费升级。
2. `services/waline/` 是独立服务部署根目录，基于 Waline 官方模板，固定服务端 1.42.0。不要把整个博客根目录作为评论后端上传，也不要为了后端上线推送博客 main。
3. 在 Neon 新建专用空数据库，执行 `services/waline/waline.pgsql`。这是初始化脚本，仅用于空数据库，不要在已有评论的库上重复执行。
4. 在 Vercel 服务项目中填写 `services/waline/.env.example` 列出的环境变量。填入 Neon 的真实连接信息，端口 5432，SSL 开启。不要同时保留指向不同数据库的 PG_* 与 POSTGRES_* 变量。
5. 填入真实 SERVER_URL，并在 SECURE_DOMAINS 中补充其域名（不含协议），保留博客域名、localhost 与 127.0.0.1。此配置用于来源限制，并不能代替反刷机制。
6. 重新部署使配置生效。随后立即访问 `<服务地址>/ui/register`，由站长设置管理员账号和密码；第一个注册用户成为管理员。不要先把服务地址填入博客或公开分发。
7. 管理员就绪后，将根目录 `.env.example` 复制为 `.env.local`，填入 `PUBLIC_WALINE_SERVER_URL=https://实际服务域名`。这个地址是公开配置；数据库密码、JWT、管理员凭据不能放入 PUBLIC_* 配置。
8. 重新构建并启动本地预览，在浏览器中验证真实留言、回复、删除、频率限制及刷新持久化。

评论设置：访客登录入口关闭；昵称必填，邮箱和网站选填。关闭人工审核、图片上传、动图搜索和统计。隐藏地区及设备信息；不设置邮件通知。普通评论立即公开，IP 提交间隔 60 秒，垃圾留言由站长事后管理。当前模板关闭 Akismet 外部转发，没有宣称具备完整自动反垃圾能力；若出现持续刷屏，再配置 Turnstile 的前后端密钥。

## 测试与正式评论隔离

文章使用 `/posts/<稳定标识>/`，友链使用 `/friends/`。改标题不影响评论，改标识会产生新的评论区。

开发模式、BLOG_PREVIEW 构建和 localhost/127.0.0.1 访问统一增加 `/__preview__` 前缀。例如测试文章是 `/__preview__/posts/ba-zhichi/`。这是防止误混入正式评论的命名约定，不是私密权限隔离：测试内容仍由云端保存，不要填写私人信息。

测试留言请写明“功能测试”，管理员验证完后删除。没有后端时只验收页面与未开通提示，不把模拟结果记为真实服务通过。

## 管理、备份与恢复

管理入口为 `<服务地址>/ui`。站长登录后处理回复、垃圾评论和数据导出；访客不需要登录。
定期在 Waline 管理后台导出评论，将备份保存在公开 GitHub 仓库之外。数据库完整备份使用 Neon 提供的 PostgreSQL 导出方式，包含私密邮箱/IP/账户数据，不可公开提交。导入或迁移前先另做备份，在测试服务验证，再切换公开 serverURL。

如果服务暂时不可用，评论区域提供重新连接按钮，文章、友链与音乐仍可使用。检查 Vercel 部署日志、Neon 连接与免费额度；不要通过关闭 SSL 或公开数据库密码来处理故障。

## 后续正式上线

站点默认评论地址为 https://ltisatis-comments.vercel.app，可用构建环境变量 PUBLIC_WALINE_SERVER_URL 覆盖。现有发布工作流无需新增配置。修改后执行检查、构建并推送 main，由 GitHub Actions 发布。仅本地 .env.local 不会随 GitHub Actions 自动生效。正式部署不设置 BLOG_PREVIEW。保留固定依赖版本和两个项目各自的 pnpm 锁文件。
